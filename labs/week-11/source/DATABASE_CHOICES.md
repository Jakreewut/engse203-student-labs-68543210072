# บันทึกการเลือกใช้ฐานข้อมูลและสถาปัตยกรรม (CP41)

เอกสารฉบับนี้จัดทำขึ้นเพื่อตอบคำถามและบันทึกความเข้าใจจากบทอ่านเพิ่มเติม (บทที่ 8: ทางเลือกฐานข้อมูล) ในรายวิชา ENGSE203

### 1. ทำไมโปรเจกต์นี้จึงเลือก SQLite แทน MongoDB?

โปรเจกต์ระบบแจ้งซ่อมและบริการของวิทยาเขต (Campus Service Request) มีโครงสร้างข้อมูลที่แน่นอนและมีความสัมพันธ์ที่ชัดเจนระหว่างตารางผู้ใช้งาน (`users`) และตารางคำร้อง (`requests`) โดยคำร้องทุกใบต้องอ้างอิงถึงผู้ใช้งานผ่าน Foreign Key (`requester_id`) เพื่อป้องกันข้อมูลซ้ำซ้อนและรักษาความถูกต้องของข้อมูล (Data Integrity) 

ระบบฐานข้อมูลเชิงสัมพันธ์แบบ SQL เช่น SQLite จึงตอบโจทย์ได้ดีกว่า NoSQL/MongoDB เพราะสามารถกำหนด Schema, Constraints (CHECK, NOT NULL, UNIQUE) และใช้คำสั่ง `JOIN` ในการดึงข้อมูลที่เชื่อมโยงกันได้อย่างมีประสิทธิภาพ นอกจากนี้ SQLite ยังทำงานเป็นไฟล์ฐานข้อมูลในเครื่อง (`campus.db`) ทำให้สะดวกต่อการพัฒนา ทดสอบ และไม่ต้องพึ่งพาบริการภายนอก

### 2. ถ้าวันหนึ่งต้องเปลี่ยนไปใช้ MongoDB จะกระทบชั้นใดบ้าง?

หากระบบจำเป็นต้องเปลี่ยนจาก SQLite ไปใช้ MongoDB จะส่งผลกระทบต่อ 2 ชั้นหลัก คือ **ชั้น Service (`requestService.js`)** และ **ชั้น Controller (`requestController.js`)**:

1. **ชั้น Service (`requestService.js`)**: ต้องเขียนตรรกะใหม่ทั้งหมด เปลี่ยนจากการเตรียมคำสั่ง SQL (`db.prepare().run() / .all()`) ไปเป็นคำสั่งของ MongoDB Driver เช่น `collection.find()` หรือ `collection.insertOne()`
2. **ชั้น Controller (`requestController.js`)**: **ได้รับผลกระทบด้วย** เพราะการติดต่อฐานข้อมูล MongoDB ที่อยู่ภายนอกหรือคนละเครื่องจะต้องทำงานแบบ Asynchronous ผ่าน Network I/O ส่งผลให้ฟังก์ชันใน Service กลายเป็น Promise ดังนั้น Controller จะต้องปรับฟังก์ชันเป็น `async` และเติม `await` หน้าคำสั่งที่เรียก Service ทุกจุด

*หมายเหตุ: สำหรับชั้น Frontend จะไม่ได้รับผลกระทบใด ๆ ตราบใดที่ API Contract และ JSON ที่ส่งออกไปยังคงรูปแบบเดิม*

### 3. Asynchronous (async/await) จำเป็นเมื่อไร และไม่จำเป็นเมื่อไร?

- **จำเป็นเมื่อ**: มีการทำงานที่ต้อง **"รอ"** ทรัพยากรภายนอกหรือระบบที่ทำงานอยู่นอกโปรเซสของเครื่อง เช่น การส่งคำขอข้ามเครือข่าย (Network I/O) การเชื่อมต่อไปยังฐานข้อมูลคนละเครื่อง (เช่น MongoDB Atlas หรือ PostgreSQL Cloud) หรือการอ่านไฟล์ขนาดใหญ่ เพื่อไม่ให้เธรดหลักของ Node.js ถูกบล็อก (Non-blocking I/O) และสามารถรับคำขออื่นต่อได้
- **ไม่จำเป็นเมื่อ**: การทำงานเป็นแบบ In-Memory หรือการทำงานกับทรัพยากรในเครื่องที่รวดเร็วมาก เช่น SQLite ผ่านไดรเวอร์ `node:sqlite` (`DatabaseSync`) ที่เป็นไฟล์ภายในเครื่องเดียวกัน ซึ่งการประมวลผลคำสั่ง SQL เกิดขึ้นในหน่วยความจำและระบบไฟล์ทันทีโดยไม่ต้องรอเครือข่าย การเขียนโค้ดแบบ Synchronous จะอ่านง่ายและตรงไปตรงมากว่า

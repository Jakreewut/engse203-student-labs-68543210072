# B1 · บันทึกการแก้บั๊ก (กรอกให้ครบทั้ง 6 จุด)

> แต่ละบั๊กให้เขียน 4 อย่าง: ไฟล์ · บรรทัด · สาเหตุ (ทำไมทำงานผิด) · แก้อย่างไร
> เขียนด้วยคำของตัวเอง — จุดนี้จะถูกถามใน oral

## บั๊กที่ 1 — อาการ: Console เตือนสีเหลืองเรื่องรายการ
- ไฟล์/บรรทัด: src/components/RequestList.jsx
- สาเหตุ:มีการใช้คำสั่ง map เพื่อวนลูปสร้างรายการ Component <RequestCard> แต่ไม่ได้กำหนด prop key ทำให้ React แจ้งเตือนเพราะ React ต้องการ key 
  เพื่อใช้ติดตามและแยกแยะว่ารายการไหนมีการเปลี่ยนแปลง เพิ่ม หรือลบใน DOM
- แก้อย่างไร: พิ่ม key={request.id} เข้าไปที่ <RequestCard>

## บั๊กที่ 2 — อาการ: ตัวเลข "รอดำเนินการ" ในแผงสรุปไม่ตรงกับที่เห็น
- ไฟล์/บรรทัด: src/pages/DashboardPage.jsx
- สาเหตุ: ในการคำนวณ object summary ตรง key ที่ชื่อ pending โค้ดระบุเงื่อนไขการกรอง (filter) ผิด โดยไปนับจำนวนจากสถานะ 'completed' แทนที่จะเป็น 
  'pending'
- แก้อย่างไร: แก้ไขเงื่อนไขการ filter ของ pending เป็น request.status === 'pending'

## บั๊กที่ 3 — อาการ: กดตัวกรอง "รอดำเนินการ" แล้วได้รายการที่ไม่ใช่
- ไฟล์/บรรทัด: src/pages/DashboardPage.jsx
- สาเหตุ: ในการสร้างตัวแปร filteredRequests โค้ดระบุเงื่อนไขเป็น request.status !== statusFilter ทำให้เวลากดปุ่มกรองสถานะ 
  ระบบจะแสดงรายการทุกสถานะยกเว้นสถานะที่ผู้ใช้เลือก
- แก้อย่างไร: เปลี่ยนตัวดำเนินการเปรียบเทียบจาก !== เป็น === เพื่อให้กรองเฉพาะรายการที่สถานะตรงกับตัวกรองที่เลือก

## บั๊กที่ 4 — อาการ: เปลี่ยน URL จาก REQ-001 เป็น REQ-002 แล้วข้อมูลไม่เปลี่ยน
- ไฟล์/บรรทัด:src/pages/RequestDetailPage.jsx
- สาเหตุ:useEffect ที่ใช้โหลดข้อมูลคำร้อง ไม่ได้ใส่ requestId ไว้ใน Dependency Array (ใส่ไว้เพียง [reloadKey]) ทำให้เมื่อผู้ใช้เปลี่ยน URL ค่า 
  requestId จะเปลี่ยนไป แต่ React ไม่ยอมรัน useEffect ซ้ำเพื่อดึงข้อมูลใหม่
- แก้อย่างไร: เพิ่ม requestId เข้าไปใน Dependency Array เป็น [requestId, reloadKey] เพื่อให้ React ทราบว่าต้องรัน Effect 
  ดึงข้อมูลใหม่ทุกครั้งที่ URL เปลี่ยน

## บั๊กที่ 5 — อาการ: กด "ลบ" แล้วรายการยังอยู่ ต้องรีเฟรชถึงหาย
- ไฟล์/บรรทัด: src/pages/DashboardPage.jsx (ในฟังก์ชัน handleDelete)
- สาเหตุ: หลังจากเรียก deleteRequest สำเร็จ โค้ดเรียกใช้คำสั่ง setRequests(requests) ซึ่งเป็นการนำ state requests ชุดเดิม 
  (ที่ยังไม่ได้ลบรายการออก) มาอัปเดตหน้าจอ ทำให้หน้าจอไม่เปลี่ยน
- แก้อย่างไร: เปลี่ยนคำสั่งเป็น setRequests(nextRequests) เพื่อนำข้อมูลชุดใหม่ (ที่รายการถูกลบออกไปแล้ว) มาอัปเดต state ให้หน้าจอสะท้อนผลทันที

## บั๊กที่ 6 — อาการ: กด "Reset Demo Data" แล้วหน้าพัง/ว่างเปล่า
- ไฟล์/บรรทัด: src/pages/DashboardPage.jsx (ในฟังก์ชัน handleReset)
- สาเหตุ: ค้ดเรียกใช้คำสั่ง setRequests(resetRequests()) โดยลืมใส่คีย์เวิร์ด await เนื่องจาก resetRequests() เป็น asynchronous function 
  จึงคืนค่ามาเป็น Promise ทำให้ State กลายเป็น Promise Object แทนที่จะเป็น Array ของข้อมูล React จึงเรนเดอร์ไม่ได้และเกิดข้อผิดพลาด
- แก้อย่างไร: เพิ่ม await ไว้หน้าฟังก์ชัน เพื่อรอให้ได้ข้อมูล Array จริงๆ ก่อนนำไปเซ็ต State เป็น setRequests(await resetRequests())
